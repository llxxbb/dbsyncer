## 背景

系统启动过程中，存在创建多个系统配置（SystemConfig）和用户配置（UserConfig）的可能性。具体表现为：MySQL 配置库 `dbsyncer_config` 表中出现多条 `TYPE='system'` 的记录，导致配置读取不确定（`list.get(0)` 返回哪条随机），用户编辑的配置可能在重启后"丢失"或"被覆盖"。

**触发场景**：
1. 系统启动时，Tomcat 端口在 `onRefresh()` 阶段已绑定（`ServletWebServerApplicationContext.createWebServer()`），而配置预加载挂在 `ContextRefreshedEvent`（`finishRefresh()` 才发布）→ 端口先开、配置后进缓存。
2. 启动窗口内，已打开的浏览器访问 `/` 或 `/login.html`（permitAll）→ `DefaultController` 调用 `getSystemConfig()` → 缓存为空 → 触发创建并写库。
3. `AppConfigServiceImpl` 构造函数（commit `085b81dd3`）在 bean 实例化阶段调用 `getSystemConfig()` → 每次启动无需浏览器也会 INSERT 一条新配置。
4. 定时任务（`MonitorServiceImpl` 实现 `ScheduledTaskJob`）在启动期调用 `getSystemConfig()` → 同样触发创建。

**根因链**（4 条，缺一条都堵不干净）：
- R1 启动窗口：Tomcat 端口绑定早于配置预加载（`PreloadTemplate:79-93`）。
- R2 "缺失即创建"的判据是内存缓存（`SystemConfigServiceImpl:77-89`、`UserConfigServiceImpl:229-242`），窗口内必空。
- R3 `AppConfigServiceImpl:33-37` 构造函数在预加载前创建配置。
- R4 `ProfileComponentImpl:105-110` 取 `list.get(0)`，MySQL 排序 `order by update_time, create_time desc`（`update_time` 漏了 desc）→ 多行时哪条生效随机。

**用户决策**：
- 存量多条配置：告警 + 手工 SQL 清理（最稳）。
- 启动窗口 UX：优先尝试端口延迟开放；如不可行则用 503 启动页。
- DB 层唯一约束：暂不需要。
- 交付形式：ADR + 方案先评审。

## 决策

我们决定采用以下分层防护方案：

### L1 端口延迟开放（消除 R1 启动窗口）

利用 Tomcat 9.0.63 的 `bindOnInit=false` 特性，延迟端口绑定直到配置预加载完成：
- 新增 `StartupGate` 接口（`dbsyncer-common`），提供 `open()` 方法。
- 新增 `WebServerFactoryCustomizer<TomcatServletWebServerFactory>` 实现（`dbsyncer-web`），为所有 Connector 设置 `bindOnInit=false`，并捕获 `ProtocolHandler` 引用注入 `StartupGate`。
- `PreloadTemplate` 在配置加载完成后调用 `StartupGate.open()` → 触发 `ProtocolHandler.resume()` → 端口绑定。
- 效果：启动窗口内端口未开放，浏览器访问显示"connection refused"，无法触发任何创建逻辑。

**超时保护**：若预加载超时（默认 30s），强制 `open()` 并记录 ERROR，避免端口永久不开放导致应用不可达。

### L2 唯一创建点（消除 R3）

- 删除 `AppConfigServiceImpl` 构造函数中的 `getSystemConfig()` 调用（保留构造函数本身用于注入）。
- 新增 `SingletonConfigBootstrap`（`dbsyncer-biz`），实现 `StartupGate` 的回调（或通过 `@Resource List<StartupGate>` 注入），在端口开放后、定时任务启动前执行：
  - 若 `profileComponent.getSystemConfig()` 为空 → 创建默认系统配置。
  - 若 `profileComponent.getUserConfig()` 为空 → 创建默认用户配置（含 admin 用户）。
- 效果：全生命周期只有这一个创建点，懒加载仅作兜底。

### L3 确定化读取（消除 R4 影响）

- `ProfileComponentImpl.getSystemConfig()` 和 `getUserConfig()` 不再 `list.get(0)`，改为确定性选择：
  - 规则：**createTime 最早**（平手取 id 字典序最小）。
  - 理由：createTime 在配置被编辑后不变化，保证"我改的那条一直是生效的那条"。
- 若检测到多条，记录 WARN 日志（含所有 id 和保留的 id），不自动删除。

### L4 启动期重复告警（处理存量）

- 预加载完成后，检测 `system` 和 `user` 类型的配置数量：
  - 若 > 1，记录 WARN 日志：`[系统配置] 检测到 N 个重复配置，保留 id={}, 其他 id={}`。
  - 提供一次性清理 SQL（附录），由运维在业务低峰手工执行。

### 拒绝的替代方案

1. **`INSERT ... WHERE NOT EXISTS`**：
   - 判定对象错位：应用层依据缓存判空，DB 层 `NOT EXISTS` 无法阻止内存对象返回。
   - MySQL `edit` 是 `UPDATE WHERE id=?`（非 upsert），`INSERT` 影响 0 行后，后续 `edit` 静默丢失。
   - 并发下 `NOT EXISTS` 本身不可靠（需唯一约束）。
   - 层次错位：`StorageService.add` 是通用 SPI，塞入 `type='system'` 业务规则违反"数据库只做存储检索"约定。

2. **DB 层唯一约束（生成列 + 唯一索引）**：
   - 需要存量表 DDL 迁移 + SPI 扩接口（`insertIfAbsent`）。
   - MySQL/disk 两种存储行为分叉，测试面大。
   - 当前 L1-L4 已在单实例内结构性杜绝重复，暂不需要。

3. **503 启动页**：
   - 端口延迟开放已验证可行（Tomcat `bindOnInit=false`），无需额外 Filter。
   - 若未来需要更友好的 UX（如显示进度），可再叠加。

## 影响

- **技术影响**：
  - 新增 `StartupGate` 接口（`dbsyncer-common`），`PreloadTemplate` 依赖它。
  - 新增 `WebServerFactoryCustomizer` 实现（`dbsyncer-web`），捕获 `ProtocolHandler`。
  - 修改 `ProfileComponentImpl`、`SystemConfigServiceImpl`、`UserConfigServiceImpl`、`AppConfigServiceImpl`。
  - 不改变存储 SPI（`StorageService`），disk/MySQL 行为一致。
- **团队影响**：
  - 需理解 Tomcat `bindOnInit` 特性和 Spring Boot 启动时序。
  - 需验证 `ProtocolHandler.resume()` 在 Tomcat 9.0.63 的行为（已确认支持）。
- **时间影响**：
  - 预计 1-2 天实现 + 测试。
  - 需回归测试：首次安装（无配置）、正常启动（有配置）、启动期浏览器访问、定时任务触发。

## 附录：存量清理 SQL

```sql
-- 查询重复的系统配置
SELECT id, name, create_time, update_time
FROM dbsyncer_config
WHERE type = 'system'
ORDER BY create_time ASC, id ASC;

-- 保留 createTime 最早（平手取 id 最小）的一条，删除其他
-- 注意：执行前请备份，并确认保留的 id 是正确的
DELETE FROM dbsyncer_config
WHERE type = 'system'
  AND id NOT IN (
    SELECT id FROM (
      SELECT id FROM dbsyncer_config
      WHERE type = 'system'
      ORDER BY create_time ASC, id ASC
      LIMIT 1
    ) t
  );

-- 同理处理 user 配置
DELETE FROM dbsyncer_config
WHERE type = 'user'
  AND id NOT IN (
    SELECT id FROM (
      SELECT id FROM dbsyncer_config
      WHERE type = 'user'
      ORDER BY create_time ASC, id ASC
      LIMIT 1
    ) t
  );
```
