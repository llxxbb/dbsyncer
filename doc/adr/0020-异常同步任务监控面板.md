# ADR 0020: 异常同步任务监控面板

**提议中** → **审查通过** → **实施中** → **已完成**

## 背景

### 问题场景

运营人员需要快速发现有问题的同步任务，但目前缺乏统一的异常监控视图：

- **异常退出的任务**：`meta.state == ERROR`，任务已停止/中断
- **有错误队列的任务**：`meta.fail > 0`，任务仍在运行但有失败记录

**当前痛点**：
- ❌ 需要在上千条任务中逐个检查
- ❌ 无法快速定位问题任务
- ❌ 没有专门的异常任务概览面板

### 现状分析

现有系统功能：
- ✅ `/index/searchMapping` 接口返回所有任务及其 Meta 信息
- ✅ 任务列表页面显示任务状态（红色三角标识 ERROR）
- ✅ 详情页面可以查看任务详情和错误信息

**缺失功能**：
- ❌ 没有专门的异常任务概览面板
- ❌ 无法按失败数排序快速定位问题任务
- ❌ 有错误队列的任务（fail > 0 但 state != ERROR）没有醒目标识

### 约束条件

1. **权限控制** - 仅 admin 角色可访问，普通用户无法看到该菜单
2. **后端筛选优先** - 减少前端传输数据量，提升性能
3. **复用现有组件** - 复用 index.html 中的任务卡片 HTML 结构
4. **向后兼容** - 不影响现有功能
5. **运营友好** - 标识清晰、排序合理、操作简单

## 决策

### 核心方案

新增「异常任务」Tab，后端筛选 + 排序，仅显示异常任务（state==ERROR 或 fail>0）。

### 状态标识设计

| 状态 | 条件 | 标识 | 说明 |
|------|------|------|------|
| 状态异常 | `meta.state == MetaEnum.ERROR (3)` | 🔴 | 红色三角图标 |
| 有错误队列 | `meta.fail > 0` | ⚠️ 50 | 黄色标签显示失败数 |
| 同时存在 | `state==3 && fail>0` | 🔴 ⚠️ 50 | **同时显示** |

**关键规则**：
- 列表仅显示异常任务（state==3 或 fail>0）
- 正常任务（state!=3 且 fail==0）不显示
- 两种标识可同时显示

### 数据排序规则

```javascript
// 后端排序（Java Stream）
List<Mapping> abnormalTasks = allTasks.stream()
    .filter(m -> m.meta.state == 3 || m.meta.fail > 0)
    .sorted((a, b) -> {
        // 第一优先级：ERROR 状态优先
        if (a.meta.state == 3 && b.meta.state != 3) return -1;
        if (a.meta.state != 3 && b.meta.state == 3) return 1;
        
        // 第二优先级：失败数倒序
        return b.meta.fail - a.meta.fail;
    })
    .collect(Collectors.toList());
```

### 数据模型

无需修改数据模型，复用现有结构：

```java
// Mapping - 已有
{
  "id": "xxx",              // Mapping ID
  "meta": {                  // Meta 对象 - 已有
    "state": 3,              // 状态：0=未运行，1=运行中，3=异常
    "success": 10000,        // 成功数
    "fail": 50,              // 失败数（错误队列）
    "errorMessage": "..."    // 错误消息（state==3 时有值）
  }
}
```

## 影响评估

### 正向影响

- ✅ **运营效率提升** - 仅显示异常任务，无需滚动查找
- ✅ **问题定位加速** - 按失败数排序，优先处理损失大的任务
- ✅ **性能优化** - 后端筛选减少数据传输量
- ✅ **维护简单** - 复用现有组件和接口

### 风险点

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 筛选数据量极大 | 后端处理慢 | 1000 条数据时 Java Stream 排序性能良好 |
| 列表渲染慢 | 前端渲染耗时 | 复用公共 HTML 片段，减少 DOM 操作 |
| 兼容性问题 | 现有功能被破坏 | 新增独立 Tab，不影响现有任务页面 |

### 向后兼容性

- ✅ **接口无变化** - 新增 `/abnormalTasks` 接口，不影响原有接口
- ✅ **现有页面无影响** - 只新增独立页面
- ✅ **数据无迁移** - 无需数据库变更

## 实施细节

### 后端改动

#### 1. 新增 Controller 方法

```java
// IndexController.java
@GetMapping("/abnormalTasks")
public RestResult getAbnormalTasks() {
    List<Mapping> allMappings = mappingService.getAllMappings();
    
    List<Mapping> abnormalTasks = allMappings.stream()
        .filter(m -> m.getMeta().getState() == 3 || m.getMeta().getFail() > 0)
        .sorted((a, b) -> {
            // ERROR 状态优先
            if (a.getMeta().getState() == 3 && b.getMeta().getState() != 3) return -1;
            if (a.getMeta().getState() != 3 && b.getMeta().getState() == 3) return 1;
            // fail 倒序
            return b.getMeta().getFail() - a.getMeta().getFail();
        })
        .collect(Collectors.toList());
    
    return RestResult.restSuccess(abnormalTasks);
}
```

// dbsyncer-web/src/main/resources/static/js/abnormalTasks.js

$(function() {

    $.loadingT(true);

        if (data.success) {
            renderTaskList(data.result);
        }

}

    </div>`;
