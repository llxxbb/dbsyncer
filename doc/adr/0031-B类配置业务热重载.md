## 背景

ADR-0029 将配置分为 A/B/C 三类，其中 B 类（线程池、缓冲区）定义为"需重启生效"。
ADR-0030 消除了 Sidecar，引入 `ExecutorFactory` 延迟创建线程池，`AbstractBufferActuator` 延迟初始化队列。

当前 B 类配置变更后的重启由 `SelfRestartService` 执行，存在两个问题：

**问题一：环境检测误判导致"自杀不活"。** `isSystemdManaged()` 检测 `/proc/1/comm` 是否为 `systemd`，实际检测的是"操作系统是否使用 systemd 启动"，而非"当前进程是否作为 systemd 服务运行"。在开发机终端运行 `java -jar` 时，PID 1 永远是 systemd，检测返回 `true`，代码执行 `System.exit(0)` 后进程直接退出，无守护进程拉起。

**问题二：进程级重启代价过高。** 即使环境检测正确，进程重启意味着：Kafka/DB 连接全断、正在执行的同步任务中断、队列中未处理的数据丢失、上下游需要重连。对于仅修改线程池参数或缓冲区周期这种场景，代价不成比例。

**根因**：B 类配置中，真正"快照"了配置值的只有两处：
- `ExecutorFactory` — DCL 缓存线程池（core/max/queue），创建后永不刷新
- `AbstractBufferActuator` — `LinkedBlockingQueue` 容量 + 定时调度周期，创建后永不刷新

其余 B 类参数（`bufferPullCount`、`bufferWriterCount`）**已经是动态读取的**（每次 `submit()` 调用 `getBufferProps()`），改完配置下一次消费就生效。

## 决策

**用业务层热重载替代进程级重启。** 不重启进程，不重启 Spring 容器，只重建持有缓存资源的组件。

### 1. ExecutorFactory：清空缓存，DCL 重建

```java
public synchronized void reload() {
    logger.info("[ExecutorFactory] 热重载...");
    // shutdown 已配置 waitForTasksToCompleteOnShutdown=true, awaitTerminationSeconds=30
    shutdown(generalExecutor, "generalExecutor");
    shutdown(storageExecutor, "storageExecutor");
    shutdown(dispatchExecutor, "dispatchExecutor");
    generalExecutor = null;   // 下次 get*() 时 DCL 从 ConfigRegistry 读新值重建
    storageExecutor = null;
    dispatchExecutor = null;
}
```

**数据安全性**：线程池不持有业务数据，`shutdown()` 等待当前任务完成后关闭，零丢失。

### 2. AbstractBufferActuator：排空-切换

队列替换的核心风险是竞态丢数据。采用**排空-切换**策略：标记只出不进 → 等待消费者排空队列 → 替换队列 → 恢复。

#### 2.1 新增 volatile 标志

```java
private volatile draining = false;
```

#### 2.2 offer() — 排空中阻塞等待

```java
@Override
public void offer(BufferRequest request) {
    ensureInitialized();
    // 排空中：阻塞等待，不丢数据
    while (draining) {
        try { Thread.sleep(10); } catch (InterruptedException e) {
            Thread.currentThread().interrupt(); return;
        }
    }
    if (queue.offer((Request) request)) {
        return;
    }
    if (isRunning(request)) {
        offerFailed(queue, (Request) request);
    }
}
```

#### 2.3 reload() — 排空 + 替换 + 重调度

```java
public void reload() {
    // ① 标记只出不进
    draining = true;

    try {
        // ② 主动触发一次消费，不等调度周期
        run();

        // ③ 等待队列排空
        long timeout = 30_000L;
        long deadline = System.currentTimeMillis() + timeout;
        while (!queue.isEmpty() && System.currentTimeMillis() < deadline) {
            try { Thread.sleep(50); } catch (InterruptedException e) {
                Thread.currentThread().interrupt(); break;
            }
        }

        if (!queue.isEmpty()) {
            logger.warn("[{}] 队列排空超时({}ms)，剩余 {} 条，跳过队列替换",
                    getClass().getSimpleName(), timeout, queue.size());
            return;  // 不替换，保持旧队列
        }

        // ④ 队列已空，替换
        int newCapacity = getBufferQueueCapacity();
        this.queue = new LinkedBlockingQueue<>(newCapacity);
        logger.info("[{}] 队列已替换: capacity={}", getClass().getSimpleName(), newCapacity);
    } finally {
        // ⑤ 恢复
        draining = false;
    }

    // ⑥ 重注册调度（周期可能也变了）
    reschedule();
}
```

#### 2.4 reschedule() — 重新注册定时调度

```java
public void reschedule() {
    if (taskKey != null) {
        scheduledTaskService.stop(taskKey);
    }
    if (taskKey == null) {
        taskKey = UUIDUtil.getUUID();
    }
    // getBufferPeriodMillisecond() 每次从 ConfigRegistry 动态读取
    scheduledTaskService.start(taskKey, getBufferPeriodMillisecond(), this);
    logger.info("[{}] 调度已重新注册: period={}ms",
            getClass().getSimpleName(), getBufferPeriodMillisecond());
}
```

#### 2.5 时序图

```
上游线程          消费者(定时调度)        reload线程
   │                  │                    │
   ├─ offer(data1)    │                    │
   │  draining=false  │                    │
   │  queue.offer ✓   │                    │
   │                  │                    │

   │                  │  poll(data1)       │

```

### 3. SelfRestartService 改造

`SelfRestartService.scheduleRestart()` 不再执行 `System.exit(0)`，改为委托 `BusinessReloader` 执行业务热重载。

```java
public void scheduleRestart(List<String> changedConfigKeys, String currentUser) {
    // 1. 发送通知（同上）
    ...

    // 2. 延迟后执行业务重载
    CompletableFuture.runAsync(() -> {
        try {
            Thread.sleep(RESTART_DELAY_SECONDS * 1000L);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }

        logger.info("===== 业务热重载开始 =====");
        businessReloader.reload(changedConfigKeys);
        logger.info("===== 业务热重载完成 =====");
    });
}
```

### 4. BusinessReloader：编排组件

```java
@Component
public class BusinessReloader {

    @Resource
    private ExecutorFactory executorFactory;

    @Resource
    private List<BufferActuator> bufferActuators;  // Spring 自动收集

    public void reload(List<String> changedKeys) {
        if (changedKeys.contains("executors")) {
            executorFactory.reload();
        }

        if (changedKeys.contains("buffers")) {
            for (BufferActuator actuator : bufferActuators) {
                actuator.reload();  // 排空-切换 + 重调度
            }
        }
    }
}
```

### 6. 各参数生效方式汇总（保留原内容）

| 参数 | 当前行为 | 热重载方案 | 数据风险 |
|------|----------|-----------|---------|
| `bufferPullCount` | 已动态读取（每次 `submit()` 调 `getBufferPullCount()`） | 无需处理 | 无 |
| `bufferWriterCount` | 已动态读取（每次 `submit()` 调 `getBufferWriterCount()`） | 无需处理 | 无 |
| `bufferPeriodMillisecond` | 快照在定时调度周期里 | `reschedule()` 重注册 | 无 |
| `bufferQueueCapacity` | 快照在队列构造里 | 排空-切换 | 零丢失（排空前阻塞等待） |
| `ExecutorProps.*` | 快照在线程池里 | `reload()` 清空缓存 | 零丢失（等待完成） |

## 影响

- **技术影响**：
  - 消除 `SelfRestartService` 对进程守护（systemd/docker）的依赖
  - B 类配置变更从"进程级重启（5-15 秒中断）"降级为"业务热重载（< 1 秒，上游短暂阻塞）"
  - 不引入新依赖，不需要升级 Spring 版本
  - `AbstractBufferActuator` 新增 `draining` 标志和 `reload()` / `reschedule()` 方法
  - `ExecutorFactory` 新增 `reload()` 方法
  - 新增 `BusinessReloader` 组件

- **UI 影响**：
  - Tab 标签：⚠ → ⟳，title 从"需重启"改为"自动热重载"
  - 保存提示：从"需重启应用生效"改为"正在热重载..."
  - 运行时 Tab：删除"启用自重启"checkbox（热重载始终可用）
  - 删除 `RuntimeProps.selfRestartEnabled` 字段

- **团队影响**：
  - 开发环境修改 B 类配置后无需手动重启，提升开发效率
  - 生产环境不再依赖 systemd/docker 守护进程即可热更新配置

- **时间影响**：
  - 改动涉及 `ExecutorFactory`、`AbstractBufferActuator`、`SelfRestartService`、`ConfigServiceImpl`、`RuntimeProps`
  - 新增 `BusinessReloader` 一个文件
  - UI 调整：`system.html`、`system/index.js`
  - 预计 1-2 天完成
