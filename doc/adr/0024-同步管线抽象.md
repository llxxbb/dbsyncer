## 背景

`FullSyncExecutorImpl.processTableGroupDataBatch` 和 `MetaBufferActuator.distributeTableGroup` 存在高度重复的同步流程：`pick → enrich → convert → writeBatch → postProcess`。两处代码各自维护，修改一处易遗漏另一处，维护成本高。

## 决策

引入同步管线抽象，核心设计：

1. **`SyncPipeline`**：定义 `pick → enrich → convert → writeBatch` 骨架，提供两个重载 `execute` 方法分别对应全量和增量
2. **`SyncTask` 值对象**：封装 `Mapping + TableGroup + Meta`，构造时传入，减少 `execute()` 参数
3. **Cursor 持久化**：全量独有逻辑，留在 `FullSyncExecutorImpl` 调用方处理

## 影响

- **技术影响**：新增 2 个类（`SyncPipeline`、`SyncTask`），修改 2 个文件（`FullSyncExecutorImpl`、`MetaBufferActuator`）
- **团队影响**：无，纯内部重构，外部接口不变
- **时间影响**：约 0.5 天
