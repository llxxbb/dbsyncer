## 背景

系统已有"异常任务"页面（`/index/abnormalTasks`），展示 `state == ERROR(3)` 或 `fail > 0` 的 Mapping，但需要管理员主动打开页面才能发现。当异常任务长时间无人关注时，问题可能持续恶化。

同时，`MonitorServiceImpl` 已注册了预警定时任务（`scheduledTaskService.start(m.getAlertCron(), this)`），cron 默认 `0 */10 * * * ?`（每 10 分钟），但 `run()` 方法为空——UI 上标注"此功能未实现"。通知基础设施（邮件 + 钉钉、分组配置、`MessageService`）已完备。

**目标**：填充 `MonitorServiceImpl.run()` 的巡检逻辑，使异常任务能自动报警到已启用的通知通道。

## 决策

### 1. 实现位置

直接在 `MonitorServiceImpl.run()` 中实现，复用已注册的定时任务调度。不新建 Service、不引入新框架。

### 2. 异常任务判定

与 `IndexController.getAbnormalTasks()` 保持一致：

```
mapping.meta.state == MetaEnum.ERROR.getCode() (3)  ||  mapping.meta.fail > 0
```

### 3. 报警策略

- **每次全量报告**：每次巡检发现异常任务时，列出全部异常任务清单（名称、ID、状态、失败次数、错误摘要）。
- **无异常则静默**：不发送"一切正常"的消息。
- **不做去重**：同一任务持续异常时，每次巡检都会出现在报告中。默认 10 分钟间隔下噪音可控，且用户可通过通知设置排除此类型。

### 4. 通知类型

新增 `NotifyType.ABNORMAL_TASK_PATROL`，用户可在通知设置中单独排除/保留。

### 5. 消息格式

Markdown 格式，复用 `MessageService.sendMessage(title, content, type)` 走 `CompositeNotifyService`：

```
### DBSyncer 异常任务巡检

**巡检时间**: 2026-09-23 14:00:00
**异常数量**: 3

| 任务名称 | ID | 状态 | 失败次数 | 错误摘要 |
|---------|-----|------|---------|---------|
| 用户同步 | abc | 异常 | 15 | Connection refused |
| 订单同步 | def | 运行中 | 3 | Duplicate key |
```

### 6. 调度间隔

保持 `alertCron` 现有默认值 `0 */10 * * * ?`（每 10 分钟），用户可在"系统设置 → 监控定时任务"中修改。

### 7. 依赖注入

`MonitorServiceImpl` 需新增注入：

- `MappingService`：获取全量 Mapping 列表
- `MessageService`：发送通知

## 影响

- **技术影响**：
  - 改动 3 个文件：`NotifyType.java`（+1 枚举）、`MonitorServiceImpl.java`（实现 run()）、`system.html`（去掉"未实现"提示）
  - 零新依赖，零新模块，复用现有通知链
  - `run()` 执行频率受 alertCron 控制，单次查询 `mappingService.getMappingAll()` 为内存操作，性能开销可忽略

- **团队影响**：无，单人可完成

- **时间影响**：预计 30 分钟完成实现 + 自测
