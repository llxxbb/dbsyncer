## 一、LOG_LEVEL 设计决策 ✅

### 新设计：由调用端自行决定

**优势**：
- ✅ 灵活性高：根据业务场景选择级别
- ✅ 职责清晰：业务逻辑决定日志级别
- ✅ 兼容性好：提供默认方法兼容旧代码
- ✅ 可扩展：新增场景无需改接口

**接口签名**：
```java
// 完整方法：调用端指定日志级别
void log(Object model, LogType logType, LogLevel logLevel, String msg);

// 默认方法：自动使用 INFO 级别
default void log(Object model, LogType logType, String msg) {
    log(model, logType, LogLevel.INFO, msg);
}
```

## 六、调用端指定 LOG_LEVEL 示例

```java
// 异常 - ERROR
logService.log(mapping, LogType.INCREMENT, LogLevel.ERROR, "同步异常");

// 警告 - WARN  
logService.log(mapping, LogType.COPY, LogLevel.WARN, "配置复制");

// 常规 - INFO
logService.log(mapping, LogType.INSERT, LogLevel.INFO, "新增配置");

// 默认 - INFO (兼容旧代码)
logService.log(mapping, LogType.RUNNING);
```
