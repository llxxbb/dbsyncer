# Phase 0016: 日志查询功能分散到任务面板

## 目标

重构日志查询功能，基于**model_type + model_id**双字段实现独立日志系统。

**核心改进**：
- 数据模型：`model_type + model_id` 双字段替代单一 `mapping_id`
- 日志方法：BaseServiceImpl 统一为 `log(type, model, content)`
- TableGroup: 日志关联到父级 Mapping，避免分散

## 范围

### 在 scope

- 修改日志表结构，添加 `model_type`、`model_id` 字段（合并 `LOG_TYPE` 和 `TYPE`）
- 修改 LogVo 数据模型
- 重构 BaseServiceImpl.log() 统一方法
- 更新 MonitorServiceImpl.queryLog() 和 clearLog()
- 前端新增任务日志页签，监控页面移除日志查询
- 清空历史日志数据

### 不在 scope

- 保留 TYPE 字段（合并 LOG_TYPE 和 TYPE）
- 不迁移历史日志数据

### BaseServiceImpl 重构成果

```java
protected void log(LogType logType, Object model, String message) {
    if (model == null) return;
    
    String modelType = getModelType(model);
    String modelId = getModelId(model);
    
    logService.log(logType, modelId, String.format("[%s] %s", modelType, message));
}

private String getModelType(Object model) {
    if (model instanceof ConfigModel) return "CONFIG_MAPPING";
    if (model instanceof Mapping) return "MAPPING";
    if (model instanceof TableGroup) return "TABLE_GROUP";
    return model.getClass().getSimpleName().toUpperCase();
}

private String getModelId(Object model) {
    if (model instanceof ConfigModel) return ((ConfigModel) model).getId();
    if (model instanceof Mapping) return ((Mapping) model).getId();
    if (model instanceof TableGroup) {
        TableGroup tableGroup = (TableGroup) model;
        Mapping mapping = profileComponent.getMapping(tableGroup.getMappingId());
        return mapping != null ? mapping.getId() : tableGroup.getMappingId();
    }
    return null;
}
```

### 后端架构

**核心改动**：
```java
// 废弃旧方法（清空所有日志）
@Override
public String clearLog() {  // ❌ 删除
    storageService.clear(StorageEnum.LOG, null);
    return "清空日志成功";
}

// 新增按任务清空
@Override
public String clearLog(Map<String, String> params) {
    String mappingId = params.get(ConfigConstant.CONFIG_MODEL_ID);
    Assert.hasText(mappingId, "mappingId 是必填参数");
    
    Query query = new Query();
    query.addFilter(ConfigConstant.CONFIG_MAPPING_ID, mappingId, false);
    query.setType(StorageEnum.LOG);
    storageService.delete(query);
    return "清空日志成功";
}

// 废弃旧查询（不区分任务）
@Override
public Paging queryLog(Map<String, String> params) {  // ❌ 删除
    // ...
}

// 新增按任务查询
@Override
public Paging queryLog(Map<String, String> params) {
    String mappingId = params.get(ConfigConstant.CONFIG_MODEL_ID);
    Assert.hasText(mappingId, "mappingId 是必填参数");
    
    Query query = new Query(pageNum, pageSize);
    query.addFilter(ConfigConstant.CONFIG_MAPPING_ID, mappingId, false);
    query.addFilter("logType", logType, false);
    query.addFilter("logLevel", logLevel, false);
    query.addFilter(ConfigConstant.CONFIG_MODEL_JSON, json, true);
    query.setType(StorageEnum.LOG);
    return storageService.query(query);
}
```

**关键点**：
- **不需要映射转换**：日志表直接存储 mappingId
- **查询直接过滤**：通过 `query.addFilter("mappingId", ...)` 实现
- **清空通过 delete**：通过 `storageService.delete()` 删除符合条件的记录

### 前端架构

```
任务编辑页 (edit.html)
  → Tab: 日志查询页签
  → JS: bindMappingLogEvent(mappingId)
     → 查询日志：/monitor/queryLog(mappingId, logType, logLevel, page, pageSize)
     → 清空日志：/monitor/clearLog({id: mappingId})
```

## 风险评估

| 风险 | 影响 | 可能性 | 缓解措施 |
|------|------|--------|----------|
| 表结构迁移失败 | 高 | 低 | 先备份表，再执行 ALTER |
| 旧日志代码调用遗漏 | 中 | 低 | 搜索所有 clearLog/queryLog 调用 |
| 前端页面冲突 | 低 | 中 | 使用独立函数命名空间 |
| 索引未生效 | 中 | 低 | 通过 EXPLAIN 验证 |

## 回滚方案

1. **回滚代码**: `git revert <commit-hash>`
2. **回滚数据**: 
   ```sql
   -- 删除新增字段
   ALTER TABLE dbsyncer_log DROP COLUMN mapping_id;
   ALTER TABLE dbsyncer_log DROP COLUMN log_type;
   ALTER TABLE dbsyncer_log DROP COLUMN log_level;
   ```
3. **回滚配置**: 恢复旧的 application.properties
